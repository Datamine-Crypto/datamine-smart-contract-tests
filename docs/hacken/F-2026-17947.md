Description
In LockquidityToken, the constant \_percentBurnMultiplier is set to 1 instead of 10000. This value serves as the default burn multiplier returned when a user has not burned any LOCK tokens or when no global burns have occurred. The multiplier system uses a 10000-base for representing 1.0x (four decimal precision), meaning a value of 1 represents 0.0001x rather than the intended 1.0x.

uint256 private constant \_percentBurnMultiplier = 1; // Should be 10000

function getAddressBurnMultiplier(address targetAddress) public view returns(uint256) {
uint256 myRatio = getAddressRatio(targetAddress);
uint256 globalRatio = getGlobalRatio();

    if (globalRatio == 0 || myRatio == 0) {
        return _percentBurnMultiplier; // Returns 1 instead of 10000
    }
    // ...

}
The getMintAmount function applies this multiplier in its calculation: blocksMintedByAmount.mul(burnMultiplier).div(\_percentMultiplier). When burnMultiplier equals 1 and \_percentMultiplier equals 10000, the division reduces the reward to 1/10000 of the expected amount. All users who have not participated in LOCK burning, and all early protocol users before any burns occur, receive only 0.01% of their expected minting rewards.

## Developer Response & Architectural Context

This behavior is an **intentional design choice** crucial to the unique tokenomics and liquidity-incentive model of Lockquidity (LOCK).

### 1. Forcing Contribution to the Permanent Liquidity Pool

Unlike the ArbiFLUX token, the core mission of Lockquidity is to act as a stability and permanent liquidity token:

- **The Core Mechanism**: When LOCK is burned, the contract automatically sells half of the burned LOCK for Ethereum and adds both back into a permanent, decentralized Uniswap liquidity pool.
- **Why the Floor is $0.0001\text{x}$ (`_percentBurnMultiplier = 1`)**: If the floor multiplier for non-burners was set to $1.0\text{x}$ (10000), users could lock ArbiFLUX and earn standard LOCK rewards indefinitely without ever contributing to the liquidity pool.
- **The Burning Incentive**: By setting `_percentBurnMultiplier = 1` (a floor of $0.0001\text{x}$), earning meaningful rewards is restricted _exclusively_ to validators who actively burn LOCK. This structure transforms burning from an optional boost into a core requirement. It ensures that 100% of validators actively fund the permanent liquidity pool, driving price stability and building deep, decentralized market reserves.

### 2. Immutability on Arbitrum (L2)

- The LockquidityToken contract is deployed on Arbitrum as a fully decentralized, immutable protocol (**no owner keys, no admin roles, and no upgradeability**).
- Even if this model diverges from the L1 ArbiFLUX tokenomics, it is an immutable law of Lockquidity on L2. The ecosystem has fully adapted to this design, successfully driving inflation down from 700% to 122% while accumulating over $135,000 in permanent pool liquidity.
- **Code Comment Discrepancy**: The inline comment in `LockquidityToken.sol` describing `_percentBurnMultiplier = 1` was copy-pasted directly from the L1 FLUX token implementation codebase (where `_percentMultiplier = 10000` is used). While the comment itself is a leftover artifact from that base code, the chosen value of `1` remains the correct, intended economic multiplier floor for Lockquidity tokenomics.
