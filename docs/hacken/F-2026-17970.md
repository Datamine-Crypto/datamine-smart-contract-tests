Description
The _swap function in LockquidityVault allocates a memory array twice in consecutive lines. The first allocation is immediately discarded when the second allocation overwrites the variable.

function _swap(address _from, address _to, uint256 _amount) internal {
    IERC20(_from).approve(ROUTER, _amount);

    address[] memory path = new address[](2);  // First allocation (wasted)
    path = new address[](2);                   // Second allocation (overwrites)
    path[0] = _from;
    path[1] = _to;
    // ...
}
The first new address[](2) allocates memory that is never used, wasting approximately 200 gas per _swap call.

## Developer Response & Architectural Context

This behavior is an **accepted code artifact** with no functional impact on the protocol's execution.

### 1. Negligible Cost and Impact
The redundant array allocation in the `_swap` function of the `LockquidityVault` is a minor copy-paste typo in the source code layout.
* **Gas Impact**: Wasting ~200 gas is mathematically and economically negligible, especially on Arbitrum (L2) where transaction fees are extremely low (amounting to a fraction of a cent).
* **Zero Security Risk**: This duplicate allocation has no impact on safety, swap execution, routing correctness, or liquidity generation.

### 2. Contract Immutability
The `LockquidityVault` is already deployed on Arbitrum L2 as a fully decentralized, ownerless, and immutable contract with **no upgrade path**. As a result, this minor gas overhead is permanent and cannot be modified.
