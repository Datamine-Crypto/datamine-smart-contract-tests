Description
In Flux, the state variables l2Gateway and l1Address are set once in the constructor and never modified, yet they lack the immutable keyword:

contract Flux is ERC777, IArbToken {
    address public l2Gateway;
    address public override l1Address;
}
Regular state variables require SLOAD operations (2100 gas after EIP-2929) on every read. The onlyGateway modifier reads l2Gateway on each bridgeMint and bridgeBurn call:

modifier onlyGateway() {
    require(msg.sender == l2Gateway, "ONLY_GATEWAY");
    _;
}
Declaring these variables as immutable embeds values directly in bytecode, reducing read cost to approximately 3 gas per access. For high-frequency bridge operations, this accumulates meaningful gas savings.

## Developer Response & Architectural Context

This behavior is an **accepted gas trade-off** with no security implications for the protocol.

### 1. Effectively Read-Only
Although `l2Gateway` and `l1Address` are not marked with the `immutable` keyword in Solidity, they are written once in the constructor and have no setter functions. Thus, they are effectively read-only and structurally secure against any post-deployment modification.

### 2. Parity and Timing of Deployment
During the initial design and testing phase of the L2 Arbitrum gateway integration in 2021, using standard state variables was the standard, tested layout pattern for custom gateway implementations.

### 3. Negligible User Gas Impact
The `onlyGateway` modifier and these variables are only accessed during `bridgeMint()` and `bridgeBurn()` calls (i.e., when assets are deposited/withdrawn across the L1-L2 Arbitrum bridge). 
* These are not high-frequency operations for regular users.
* For all core user actions—such as locking DAM, burning tokens, or minting FLUX rewards—these bridge variables are never read, meaning regular users experience zero gas overhead from this setup.

### 4. Contract Immutability
The L2 `Flux` token contract is deployed on Arbitrum as an ownerless, immutable contract with **no upgrade path**. As a result, this state variable configuration is permanent.
