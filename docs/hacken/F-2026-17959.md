Description
In Flux, the constructor assigns the gateway address and includes a guard requiring the gateway storage variable to equal the zero address before assignment. Because constructor storage is always zero-initialized and the constructor runs once, this guard is unconditionally true and protects nothing.

constructor(
    address _l2Gateway,
    address _l1Counterpart
) public ERC777("Flux", "FLUX", new address[](0)) {
    require(_l2Gateway != address(0), "INVALID_GATEWAY");
    require(l2Gateway == address(0), "ALREADY_INIT");
    // ...
}
The guard is an initializer-style re-initialization check placed in a constructor context. Under direct deployment it is harmless dead code with no effect on on-chain behavior.

## Developer Response & Architectural Context

This behavior is an **accepted code artifact** with no functional impact on on-chain behavior.

### 1. Harmless Dead Code
The check `require(l2Gateway == address(0), "ALREADY_INIT")` is an initializer-style re-initialization guard placed in the constructor. While it is redundant under direct constructor execution because constructor storage is always zero-initialized, it is completely harmless and does not affect the safety or logic of token operations.

### 2. Contract Immutability
The `Flux` token contract is already deployed on Arbitrum L2 as a fully decentralized, ownerless, and immutable contract with **no upgrade path**. As a result, this redundant check is permanent.
